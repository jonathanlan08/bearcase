# Architecture

## Shape

```
┌──────────────┐   /api/* rewrite   ┌──────────────────────────────────────────────┐
│ Next.js web  │ ─────────────────▶ │ FastAPI                                      │
│ (app router) │                    │  api/routes ── deps (auth, deal scoping)     │
└──────────────┘                    │  pipeline/jobs ── ThreadRunner | poll worker │
                                    │  pipeline/process_document ── ingest/*       │
                                    │  pipeline/analyze ── engine/*, ai/*          │
                                    │  reports/assemble ── validate ── export      │
                                    │  SQLAlchemy 2 ── SQLite | PostgreSQL         │
                                    │  storage ── local dir | S3/MinIO             │
                                    └──────────────────────────────────────────────┘
```

## Request and job flow

1. **Upload** (`POST /deals/{id}/documents`): validate bytes → hash → reject duplicates → store under a server-generated key → `Document` + `DocumentVersion` → `ProcessingJob(process_document)` queued and dispatched.
2. **Process document** (job): parse by type → classify (rules; AI only when rules return unknown) → `Evidence` rows with locators; instruction-like text flagged; document → `ready`.
3. **Analyze deal** (job, `POST /deals/{id}/process`): clear derived rows → map statements to `FinancialPeriod` + extracted `FinancialMetric` → customer aggregates → model terms and `Adjustment` rows → rule-based add-back review → deal-level calculated metrics → claim extraction (provider) → verification (engine for numeric, provider + guardrails for narrative) → seed and run scenarios → findings → deal `verified`.
4. **Report** (job): assemble deterministic sections from rows → provider drafts narrative → validate citations → `Report` + `ReportCitation`; export as Markdown or PDF.
5. **Review** (`POST /claims/{id}/review`, `POST /adjustments/{id}/decision`): additive decision rows; metrics recomputed where needed; audit event.

## Job runner

`ThreadRunner` (default) executes jobs FIFO on one daemon thread inside the API process; each job runs in its own session and commits progress so pollers see live status. `SyncRunner` runs inline (tests, seed). `poll` mode leaves jobs queued for `bearcase worker`, which claims the oldest queued job; with PostgreSQL this scales to multiple workers.

## Provider interface

`AIProvider` exposes `classify`, `extract_claims`, `verify_claim`, `draft_narrative`; each returns a `ProviderResult` with the validated output, raw JSON, usage, prompt version, schema version, and input hash. `MockProvider` is rule-based and deterministic; `AnthropicProvider` uses `messages.parse` with Pydantic output schemas and the SDK's retries and timeouts. Every call is recorded as an `ExtractionRun`.

## Frontend

App Router with client pages backed by TanStack Query hooks (`components/app/hooks.ts`). The landing page renders figures from a committed JSON snapshot (`content/northstar-snapshot.json`) generated by the engine, so it never depends on the API. The Evidence Core scene is loaded dynamically with `ssr:false` behind a server-rendered static SVG.
